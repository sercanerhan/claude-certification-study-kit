title: Plan mode vs direct execution
---
## Core idea
Plan mode lets Claude read and explore the codebase and propose a plan **without changing files**. It fits big, ambiguous or architectural work, where a wrong first move means expensive rework. Direct execution fits small, well-understood changes, where planning only adds ceremony. Many real tasks combine the two: plan the approach, then execute it directly.

## What the exam tests
- Use **plan mode** for:
  - large-scale or multi-file changes (a library migration touching 45+ files);
  - multiple valid approaches (webhooks vs bot tokens vs a full app integration);
  - architectural decisions (service boundaries in a monolith split).
- Use **direct execution** for a clear scope: a single-file bug with a clear stack trace, or one added date-validation check.
- Plan mode gives safe exploration and design before you commit to changes.
- The **Explore subagent** isolates verbose discovery output and returns a summary, so the main context isn't exhausted during multi-phase tasks.
- Combine them: plan mode for investigation, then direct execution of the approved plan.

## Exam traps
- **Trap:** "start directly and switch to plan mode if it gets complex" → **Instead:** if the complexity is already stated (dozens of files, boundary decisions), plan first.
- **Trap:** direct execution with very detailed upfront instructions → **Instead:** that assumes you already know the right design without exploring.
- **Trap:** plan mode for a one-line null check with a clear stack trace → **Instead:** use direct execution. Planning adds overhead with no benefit.
- **Trap:** run a 120-file discovery in the main conversation and keep compacting → **Instead:** let an Explore subagent do the discovery and return a summary.

## Example
```
Task: migrate from moment.js to date-fns (52 files)
1. Plan mode: inventory usages, group patterns, choose a wrapper strategy, list risky files
2. Approve the plan
3. Direct execution: apply the planned changes module by module, run the tests after each
```

## Remember
- Large, ambiguous or architectural → plan mode.
- Small, clear, single-file → direct execution.
- Verbose discovery → Explore subagent with a summary back.
- Plan, then execute.
- Docs note: enter plan mode with Shift+Tab or `--permission-mode plan`. In current docs the subagent-spawning `Task` tool is called `Agent` (renamed in v2.1.63; `Task` still works as an alias).
