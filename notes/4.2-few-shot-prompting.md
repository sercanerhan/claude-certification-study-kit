## Core idea
When detailed instructions still produce output that is sometimes detailed and sometimes vague, the fix the exam wants is **few-shot examples**. A few input-to-output examples show the exact format and the judgment you expect, and Claude generalizes the pattern to new cases instead of only matching the listed ones. Examples work best on the ambiguous cases: they show *why* one choice wins over a plausible alternative.

## What the exam tests
- Few-shot is the most effective technique for **consistent, actionable format** (location, issue, severity, suggested fix) once instructions alone have failed.
- Use **2–4 targeted examples** for ambiguous cases, each with a short line of reasoning explaining why this action beat the alternative.
- Show acceptable code patterns next to real issues, so the model learns the boundary and reduces false positives on new variants.
- In extraction, examples covering **varied document structures** (inline citations vs bibliography, narrative text vs tables) fix empty or null required fields.
- Examples for **informal values** ("a couple of pallets", "about 3 weeks") reduce hallucinated precision.

## Exam traps
- **Trap:** keep adding more explicit wording to the instructions → **Instead:** add examples. The exam stem usually says that instructions were already tried.
- **Trap:** list every known bad pattern as a rule → **Instead:** use a few examples with reasoning. Rules only match what you listed, while examples generalize.
- **Trap:** split the work into two prompts ("find issues", then "write fixes") to fix format drift → **Instead:** use few-shot. The chain adds cost and does not settle the format.
- **Trap:** give 10–20 near-identical examples → **Instead:** use a few diverse ones. Similar examples teach accidental patterns.
- **Trap:** use few-shot when a deterministic guarantee is needed (for example, tool ordering before a refund) → **Instead:** enforce it in code. Few-shot is probabilistic.

## Example
```text
<example>
Document: "...as Lee et al. (2021) showed, churn fell 12%..."
Output: {"claim":"churn fell 12%","source":"Lee et al. 2021","citation_style":"inline"}
</example>
<example>
Document: "...churn fell 12% [4]."  References: [4] Lee, J. (2021) ...
Output: {"claim":"churn fell 12%","source":"Lee, J. (2021)","citation_style":"bibliography"}
Why: resolve the numbered marker to the reference list; never leave source empty.
</example>
```

## Remember
- Instructions failed → examples next.
- 2–4 targeted examples, each with reasoning for the ambiguous choice.
- Examples generalize; rule lists only match listed cases.
- Varied-format examples fix null extractions of required fields.
- Current docs say "3–5 examples, wrapped in `<example>` tags". The guide says 2–4. Both mean a few diverse ones.
