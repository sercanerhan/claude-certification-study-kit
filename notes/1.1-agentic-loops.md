## Core idea
An agentic loop works like this: send the conversation to Claude and check `stop_reason`. If it is `"tool_use"`, run the requested tools, append the results and call Claude again. If it is `"end_turn"`, stop. The model decides which tool to call next from what it has seen so far. Your code only executes tools and keeps the history intact. The Agent SDK runs this loop for you, and the exam tests how it works inside.

## What the exam tests
- The lifecycle: request → inspect `stop_reason` → execute tools → append results → next iteration.
- Continue on `"tool_use"` and terminate on `"end_turn"`. This structured field is the completion signal.
- Tool results must go back into the conversation history. Otherwise the model cannot reason about them and tends to repeat the same call.
- **Model-driven** decisions (Claude picks the next tool from context) versus **pre-configured** decision trees or fixed tool sequences.
- Known anti-patterns: parsing natural language ("I'm done") to stop, an iteration cap as the *primary* stop, and treating "the response contains text" as completion.

## Exam traps
- **Trap:** stop when the reply says something like "anything else?" → **Instead:** read `stop_reason`. Wording changes, but the structured field doesn't.
- **Trap:** stop when the response contains a text block → **Instead:** text and `tool_use` blocks can appear in the same response.
- **Trap:** `max_iterations = 10` as the termination logic → **Instead:** caps (such as the SDK's `max_turns`) are safety nets, not the main stopping mechanism.
- **Trap:** the agent loops calling the same tool with the same arguments, so raise the cap → **Instead:** check that the `tool_use` turn and its `tool_result` are actually appended.
- **Trap:** hard-code the tool order "for reliability" in open-ended tasks → **Instead:** let the model choose. Enforce order with code only where business rules require it (task 1.4).

## Example
```python
messages = [{"role": "user", "content": user_msg}]
while True:
    resp = client.messages.create(model=M, tools=TOOLS, messages=messages, max_tokens=2048)
    messages.append({"role": "assistant", "content": resp.content})
    if resp.stop_reason != "tool_use":        # "end_turn" -> done
        break
    results = [{"type": "tool_result", "tool_use_id": b.id, "content": run(b.name, b.input)}
               for b in resp.content if b.type == "tool_use"]
    messages.append({"role": "user", "content": results})   # only tool_result blocks
```

## Remember
- `tool_use` → run the tools and loop. `end_turn` → done.
- All results for one response go back in **one** user message, one `tool_result` per `tool_use` id, with no text after them.
- Missing history shows up as the same call repeated with the same arguments.
- Caps guard, they never decide completion.
- Docs note: production loops also handle `max_tokens`, `pause_turn` and `refusal`, but the exam centres on `tool_use` vs `end_turn`.
