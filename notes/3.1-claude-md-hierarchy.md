## Core idea
CLAUDE.md files are instructions that load automatically. **Where** a file lives decides **who** gets it.
- User level, `~/.claude/CLAUDE.md`: only you.
- Project level, `./CLAUDE.md` or `./.claude/CLAUDE.md`: everyone who clones the repo.
- Directory level, `sub/CLAUDE.md`: work in that subtree.

Most "Claude ignores our rule for one developer" bugs come from the wrong level. Keep large instruction sets modular with `@import` and with topic files in `.claude/rules/`.

## What the exam tests
- The hierarchy: user, project and directory. User-level files are **never** shared through version control.
- Diagnosis: a new teammate doesn't get a convention because it lives in someone's `~/.claude/CLAUDE.md`. Move it to the project file.
- `@path/to/file` imports: each package's CLAUDE.md imports only the standards files its maintainers consider relevant (`@../../standards/payments-api.md`).
- `.claude/rules/*.md` replaces a monolithic CLAUDE.md with topic files such as `testing.md`, `api-conventions.md` and `deployment.md`.
- `/memory` shows which memory files are in play. Use it to diagnose inconsistent behaviour between sessions or between developers.

## Exam traps
- **Trap:** a cache, or Claude "learning per user", explains why one developer differs → **Instead:** the instruction is at user level. Move it to project level.
- **Trap:** one 500-line CLAUDE.md with every package's rules → **Instead:** use `@import` per package, or topic files in `.claude/rules/`.
- **Trap:** README files in subfolders act as instructions → **Instead:** only CLAUDE.md files, rules and imports load as memory.
- **Trap:** a `.claude/config.yaml` mapping files to sections → **Instead:** no such mechanism exists. Use rules with `paths` frontmatter (see 3.3).

## Example
```markdown
# packages/billing/CLAUDE.md
Billing service. Follow these standards:
@../../standards/money-handling.md
@../../standards/api-errors.md
```

## Remember
- `~/.claude/CLAUDE.md` = personal, not in git. Project CLAUDE.md = team.
- Subdirectory CLAUDE.md = scoped to that directory tree.
- Use `@import` to compose standards for each package.
- `.claude/rules/` = topic files instead of one monolith.
- `/memory` = check which memory files are loaded.
- Docs note: current docs allow imports to nest at most **four hops**. They also add `CLAUDE.local.md` for personal, gitignored project notes, and recommend `/context` to see exactly which files loaded at launch. Subdirectory CLAUDE.md files load on demand when Claude touches files there.
