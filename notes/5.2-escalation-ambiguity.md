## Core idea
A support agent reaches high first-contact resolution by escalating for the right reasons, not the most cases. Valid triggers are an explicit request for a human, a policy gap or exception, and being unable to make progress. Frustration and complexity alone are not triggers. Ambiguity about *who* the customer is gets resolved by asking for another identifier, never by guessing. Calibrate this with explicit criteria and few-shot examples in the system prompt.

## What the exam tests
- Triggers: the customer asks for a human; policy is **silent or ambiguous** on the request; the agent can't make meaningful progress.
- An explicit demand for a human is honoured **immediately**, without first investigating.
- Frustration with a straightforward issue: acknowledge it, offer the resolution, and escalate only if the customer **repeats** the request.
- Sentiment and self-reported confidence are unreliable proxies for complexity.
- Multiple customer matches → ask for an additional identifier (email, phone, order number). Don't pick heuristically.
- Use explicit escalation criteria with **few-shot examples** of escalate vs resolve.

## Exam traps
- **Trap:** escalate when sentiment falls below a threshold → **Instead:** an angry customer with a simple, covered issue should be helped.
- **Trap:** route on the agent's self-rated confidence → **Instead:** it is poorly calibrated, and agents are confidently wrong on hard cases.
- **Trap:** train a classifier first → **Instead:** try explicit criteria and examples first. A classifier is disproportionate as a first step.
- **Trap:** pick the account with the most recent order when names match → **Instead:** ask for another identifier.
- **Trap:** the customer asks for a human, so "let me quickly check your order first" → **Instead:** escalate now.
- **Trap:** a competitor price-match request when policy covers only own-site drops, so the agent improvises → **Instead:** that is a policy gap, so escalate.

## Example
```text
Escalate:
- "Get me a real person" -> escalate_to_human immediately.
- Request not covered by policy (competitor price match) -> escalate with a handoff summary.
Resolve:
- "This is ridiculous, my blender arrived broken!" + photo -> acknowledge, offer replacement.
Clarify:
- get_customer returns 3 matches -> "Could you confirm the email on the account?"
```

## Remember
- Triggers: explicit request, policy gap, no progress.
- Not triggers: anger, complexity, multiple issues.
- Multiple matches → ask, don't guess.
- Fix calibration with explicit criteria plus few-shot examples first.
