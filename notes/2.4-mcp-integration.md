## Core idea
MCP servers add external tools and data to Claude Code and to Agent SDK agents. The architect's decisions are:
- **where** a server is configured: shared with the team, or personal;
- **how** secrets reach it: environment variables, never committed;
- **how** the agent learns what the server offers: rich tool descriptions, and resources that list the available content.

## What the exam tests
- **Project scope:** `.mcp.json` at the repo root, committed and shared by the team.
- **User scope:** `~/.claude.json`, for personal or experimental servers. It is not shared.
- Env var expansion in `.mcp.json`: `"GITHUB_TOKEN": "${GITHUB_TOKEN}"` (also `${VAR:-default}`). Each developer supplies their own token and no secret is committed.
- Tools from **all** configured servers are discovered at connection time and are available together.
- If the agent keeps using Grep instead of a more capable MCP tool, enrich the MCP tool's description. Say what it can do that built-ins can't, and what it returns.
- Prefer existing community servers for standard integrations such as Jira or GitHub. Build custom servers only for team-specific workflows.
- **MCP resources** expose catalogs: issue summaries, documentation trees, DB schemas. The agent then sees what exists without making exploratory tool calls.

## Exam traps
- **Trap:** commit the token in `.mcp.json`, or make everyone add the server at user scope → **Instead:** commit a project `.mcp.json` that uses `${VAR}` and document the variable.
- **Trap:** write a custom Jira MCP server → **Instead:** use the maintained community server. Build custom only for unique workflows.
- **Trap:** remove Grep so the agent is "forced" onto the MCP tool → **Instead:** fix the MCP tool description. That is the root cause.
- **Trap:** let the agent explore with list/search calls to find which schemas exist → **Instead:** publish the catalog as an MCP resource.

## Example
```json
{"mcpServers": {
  "jira": {"command": "npx", "args": ["-y", "<community-jira-server>"],
           "env": {"JIRA_TOKEN": "${JIRA_TOKEN}"}}}}
```

## Remember
- `.mcp.json` = team (committed). `~/.claude.json` = personal.
- Use `${VAR}` for secrets. Expansion works in `command`, `args`, `env`, `url` and `headers`.
- All servers' tools load together, so descriptions decide which tool gets used.
- Resources = a catalog with no tool calls.
- Docs note: current Claude Code docs name three scopes. **local** is the default: personal, for one project, stored in `~/.claude.json`. **project** is `.mcp.json`. **user** is `~/.claude.json` for all projects. Tool search can also defer loading tool definitions until they are needed. The exam uses the two-scope model.
