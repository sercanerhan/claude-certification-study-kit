## Core idea
Hooks are callbacks in your application that run at fixed points in the agent loop. **PreToolUse** fires before a tool runs and can allow it, deny it (with a reason the model sees) or rewrite its input. **PostToolUse** fires after a tool returns and can transform or annotate the result before the model reads it. Hooks run in code, so they give **deterministic** guarantees where prompt instructions only give probabilistic compliance.

## What the exam tests
- PostToolUse intercepts **results** to normalise them, for example turning Unix timestamps, ISO 8601 strings and numeric status codes into one format, even for third-party MCP tools you can't modify.
- PreToolUse intercepts **outgoing calls** to enforce compliance, for example blocking refunds over $500 and redirecting to human escalation.
- Hooks are for **guaranteed** rules. Prompts suit judgment and style.
- Choose hooks over prompt enforcement whenever a business rule must hold every time.

## Exam traps
- **Trap:** put the format conventions of every tool in the system prompt → **Instead:** normalise once in a PostToolUse hook. It's centralised, deterministic and costs no tokens.
- **Trap:** a `normalize_data` tool the agent should call after each lookup → **Instead:** that depends on the model remembering to call it.
- **Trap:** enforce the refund limit with a PostToolUse check → **Instead:** by then the refund has already executed. Block it in **PreToolUse**.
- **Trap:** remove `process_refund` entirely to be safe → **Instead:** gate only the violating calls so small refunds still resolve on first contact.
- **Trap:** use a hook to make replies "friendlier" → **Instead:** that is tone and judgment, which belongs in the prompt.

## Example
```python
async def refund_limit(inp, tool_use_id, ctx):
    if inp["tool_input"].get("amount", 0) > 500:
        return {"hookSpecificOutput": {"hookEventName": "PreToolUse",
            "permissionDecision": "deny",
            "permissionDecisionReason": "Refunds over $500 need a human: call escalate_to_human."}}
    return {}

options = ClaudeAgentOptions(hooks={
    "PreToolUse":  [HookMatcher(matcher="mcp__support__process_refund", hooks=[refund_limit])],
    "PostToolUse": [HookMatcher(matcher="^mcp__", hooks=[normalize_dates_and_status])]})
```

## Remember
- PreToolUse is **before** the call: block, allow or rewrite input (`permissionDecision`, `permissionDecisionReason`, `updatedInput`).
- PostToolUse is **after** the call: transform or annotate the result (`updatedToolOutput`, or the older MCP-only `updatedMCPToolOutput`; `additionalContext` appends).
- Matchers filter on tool names. MCP tools are named `mcp__<server>__<tool>`.
- A deny reason lets the model redirect, for example to escalation.
- Guarantee means a hook. Preference means the prompt.
