## Core idea
In a pipeline nobody can answer prompts. Claude Code must run **non-interactively** (`-p`), emit **machine-parseable** output, and get its project knowledge from files in the repo (CLAUDE.md), not from a human. Review quality also depends on **independence**: a fresh instance reviews better than the session that wrote the code.

## What the exam tests
- `claude -p "..."` (or `--print`) runs non-interactively. It prints the result and exits, so the job doesn't hang.
- `--output-format json` plus `--json-schema '<schema>'` gives structured findings your script can post as inline PR comments.
- CLAUDE.md supplies CI context: testing standards, available fixtures and review criteria.
- Session isolation: the generating session is biased towards its own decisions. Use a separate review instance.
- On re-review after new commits, include the previous findings and ask Claude to report only **new or still-unaddressed** issues, so comments aren't duplicated.
- For test generation, put the existing test files in context so Claude doesn't propose scenarios that already exist. Document what makes a test valuable in CLAUDE.md.

## Exam traps
- **Trap:** `CLAUDE_HEADLESS=true`, `--batch`, or `< /dev/null` → **Instead:** `-p`. The others don't exist or don't fix the hang.
- **Trap:** regex-parse free-text review output → **Instead:** `--output-format json` with `--json-schema`.
- **Trap:** ask the same session that generated the code to review it → **Instead:** use an independent instance.
- **Trap:** re-run the full review on every push and post everything → **Instead:** pass in the prior findings and report only the delta.

## Example
```bash
claude -p "Review the diff in pr.diff against CLAUDE.md review criteria" \
  --output-format json \
  --json-schema '{"type":"object","properties":{"findings":{"type":"array","items":{"type":"object","properties":{"file":{"type":"string"},"line":{"type":"integer"},"severity":{"type":"string"},"message":{"type":"string"}},"required":["file","line","message"]}}},"required":["findings"]}' \
  | jq '.structured_output.findings'
```

## Remember
- `-p` = no interactive hang.
- JSON output + `--json-schema` = parseable findings.
- CLAUDE.md = CI's project context.
- Independent reviewer > self-review.
- Prior findings in context → report only new issues.
- Docs note: the schema-conforming result is in the `structured_output` field of the JSON response. Current docs recommend `--bare` for CI, because it skips auto-discovery of CLAUDE.md, hooks and MCP. Pass any needed context explicitly with flags.
