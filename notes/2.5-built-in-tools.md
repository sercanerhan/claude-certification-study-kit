## Core idea
Pick the tool by **what you are searching or changing**:
- **Glob** finds files by *path/name* pattern.
- **Grep** finds *content* inside files.
- **Read** loads a whole file.
- **Write** creates or replaces a whole file.
- **Edit** swaps one exact, **unique** string for another.
- **Bash** runs commands: tests, git, builds.

Understand a codebase incrementally: Grep for entry points, Read what you found, and follow the imports. Don't read everything upfront.

## What the exam tests
- **Grep** answers "where is this text?": callers of a function, an error message, import statements.
- **Glob** answers "which files are named like this?": `**/*.test.tsx`, `db/migrations/*.sql`.
- **Edit** needs anchor text that appears exactly once. If the match is not unique, Edit fails. The reliable fallback is **Read** the full file, then **Write** the full modified content.
- Build understanding step by step: Grep → Read → follow imports → Grep the usages. Reading every file first floods the context.
- For wrapper modules, first list **every exported name** (re-exports and aliases too), then Grep for each name. Grepping only the original function name misses callers that use the alias.

## Exam traps
- **Trap:** Grep for `.test.tsx` to find test files → **Instead:** Glob `**/*.test.tsx`. You are matching *names*, not contents.
- **Trap:** Edit fails on a non-unique anchor, so retry the same Edit or set `replace_all` → **Instead:** Read + Write. `replace_all` also changes the occurrences you meant to leave alone.
- **Trap:** script a `sed -i` via Bash for one targeted change → **Instead:** Read + Write. sed is fragile on multi-line text, hard to review, and skips the file tools' safety checks.
- **Trap:** Read every file in `src/` to "understand the system" → **Instead:** Grep for entry points and trace from there.
- **Trap:** Grep only for `chargeCard` when `payments/index.ts` re-exports it as `charge` → **Instead:** list the exports, then search for each alias.

## Example
```
Goal: change the 2nd `timeout: 30` in config.ts (it appears 3 times)
Edit(old="timeout: 30") -> fails: matches 3 locations
Read(config.ts) -> modify the intended block -> Write(config.ts)
```

## Remember
- Names/paths → Glob. Contents → Grep.
- Edit = unique exact match. Non-unique → Read + Write.
- Start with Grep, then Read selectively, then follow imports.
- Find the exported names first, then Grep every alias.
- Docs note: current Claude Code docs say that on macOS/Linux, Glob and Grep may be left out of the default tool set, and Claude then searches through Bash (`find`/`grep`). The docs also list a longer, unique `old_string` as the first Edit alternative. The exam still expects Glob/Grep and the Read + Write fallback.
