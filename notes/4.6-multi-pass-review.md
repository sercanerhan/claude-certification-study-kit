## Core idea
A model reviewing its own work in the same session keeps the reasoning that produced it, so it tends to confirm its earlier decisions. A **second, independent instance** that sees only the artifact (diff, spec, tests) and not the generator's reasoning catches more subtle problems. Large reviews also suffer from **attention dilution**: some files get deep analysis, others get shallow comments, and identical code is judged differently. Split the review into per-file passes plus a cross-file integration pass.

## What the exam tests
- Self-review limitation: same-session context means confirmation bias. Neither "critique your own work" instructions nor extended thinking fixes this.
- An independent reviewer instance with no access to the generator's transcript.
- Multi-pass: per-file local analysis, then a separate integration pass for cross-file data flow, types and contracts.
- A verification pass in which the model reports **confidence per finding**, used to route findings (post automatically, or send to human triage). Thresholds are calibrated on labeled data (see 5.5).
- Relationship to 1.6 (prompt chaining) and 3.6 (session isolation in CI).

## Exam traps
- **Trap:** add "carefully review your answer before finishing" to the generation prompt → **Instead:** use a separate reviewer instance. The bias comes from the shared context.
- **Trap:** enable extended thinking for the generator → **Instead:** use an independent reviewer. More thinking within the same context still rationalizes the same choice.
- **Trap:** switch to a larger context window or bigger model for a 14-file PR → **Instead:** split into passes. Attention quality, not capacity, is the problem.
- **Trap:** run 3 full reviews and keep only issues found at least twice → **Instead:** split into focused passes. Requiring consensus suppresses real bugs that are only caught intermittently.
- **Trap:** make developers split PRs → **Instead:** fix the review architecture. Pushing the burden onto developers does not improve the system.

## Example
```text
Pass 1..N (parallel): review file_i alone → local findings (JSON)
Pass N+1: integration review → inputs: diff summary + interfaces + pass-1 findings
          focus: cross-file data flow, contract mismatches, duplicated logic
Pass N+2 (independent instance): verify each finding, add confidence 0–1
Routing: confidence ≥ calibrated threshold → inline comment; else → triage queue
```

## Remember
- Same-session self-review means confirmation bias.
- An independent instance without the generator's reasoning catches subtle bugs.
- Use per-file passes plus an integration pass. A bigger context window is not the fix.
- A consensus filter suppresses real findings.
- Calibrate confidence-based routing on labeled data before trusting it.
