## Core idea
Slash commands and skills package a repeatable workflow behind `/name`. **Location** decides who has it:
- `.claude/commands/` or `.claude/skills/` in the repo is shared by the team through git.
- `~/.claude/commands/` or `~/.claude/skills/` is personal.

Skills (`SKILL.md`) take frontmatter that controls *how* they run: an isolated context, tool limits, and an argument prompt. Use a skill for on-demand, task-specific workflows. Use CLAUDE.md for standards that must always apply.

## What the exam tests
- Use project commands in `.claude/commands/` when every developer must get the command on clone or pull.
- Skills live in `.claude/skills/<name>/SKILL.md`. Their frontmatter includes:
  - `context: fork` runs the skill in an isolated sub-agent, so verbose output (codebase analysis) or exploratory output (brainstorming) doesn't pollute the main conversation.
  - `allowed-tools` limits the skill to the tools it needs, for example file-write only, which prevents destructive Bash.
  - `argument-hint` prompts the developer for the required parameter.
- For personal tweaks, create a variant in `~/.claude/skills/` **under a different name**, so teammates are unaffected.
- Skill vs CLAUDE.md: a skill loads on demand, while CLAUDE.md is always loaded.

## Exam traps
- **Trap:** put the command in CLAUDE.md or an invented `.claude/config.json` → **Instead:** use `.claude/commands/` (or `.claude/skills/`).
- **Trap:** fix context pollution by "asking the skill to summarise" or by switching models → **Instead:** `context: fork` isolates the output.
- **Trap:** prompt text "never run destructive commands" → **Instead:** use frontmatter tool limits, which are configuration rather than hope.
- **Trap:** put workflow-specific guidance (deploy, migrations) in CLAUDE.md → **Instead:** make it a skill. Keep CLAUDE.md for universal rules.

## Example
```yaml
---
name: analyze-module
description: Deep dependency and coverage analysis of one module
context: fork
allowed-tools: Read, Grep, Glob
argument-hint: "[module-path]"
---
Analyze $ARGUMENTS and return a 10-line summary of risks.
```

## Remember
- `.claude/commands/` = team. `~/.claude/commands/` = personal.
- `context: fork` = isolate verbose or exploratory output.
- `allowed-tools` = scope the tools. `argument-hint` = ask for the argument.
- Personal variant = different name in `~/.claude/skills/`.
- Docs note: in current Claude Code, commands are merged into skills. Both create `/name`, and a skill wins over a command with the same name. Also, `allowed-tools` now **pre-approves** the listed tools, while `disallowed-tools` removes tools. For the exam, treat `allowed-tools` as the restriction knob, as guide v1.0 does.
