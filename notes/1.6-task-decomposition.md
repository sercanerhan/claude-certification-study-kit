## Core idea
There are two ways to split a big job. **Prompt chaining** is a fixed sequence of focused steps, which suits work whose shape you know in advance (a multi-aspect review). **Dynamic, adaptive decomposition** is a plan that creates new subtasks from what each step uncovers, which suits open-ended investigation where the useful leads only appear along the way. Choosing the pattern that matches the task is the architect's decision.

## What the exam tests
- When to use fixed sequential pipelines vs adaptive decomposition based on intermediate findings.
- Prompt chaining for reviews: analyse each file on its own, then run a **cross-file integration pass**.
- Splitting large reviews into per-file local passes plus an integration pass avoids **attention dilution** (shallow or contradictory feedback).
- Adaptive investigation plans that generate subtasks as discoveries are made.
- Open-ended tasks ("add comprehensive tests to a legacy codebase"): first **map the structure**, then **identify high-impact areas**, then build a **prioritised plan** that adapts as dependencies appear.

## Exam traps
- **Trap:** an open-ended research question gives generic answers, so add more searches to the fixed pipeline → **Instead:** switch to dynamic decomposition. More volume doesn't follow leads.
- **Trap:** write the complete subquestion list up front → **Instead:** for open-ended work the list has to change as findings arrive.
- **Trap:** a 14-file PR in one pass, fixed with a bigger context window → **Instead:** per-file passes plus an integration pass. Attention, not capacity, is the issue.
- **Trap:** "add tests everywhere" by writing tests file by file in alphabetical order → **Instead:** map first, prioritise by impact, then adapt.
- **Trap:** adaptive decomposition for a predictable checklist review → **Instead:** prompt chaining is simpler and more consistent there.

## Example
Fixed chain (predictable): `security pass → performance pass → style pass → merge findings`.

Adaptive (open-ended): "Why did heat-pump adoption stall in some EU countries?"
1. Initial scan of adoption data. Finding: a subsidy change in 2023.
2. New subtask: compare subsidy designs across countries. Finding: installer shortage.
3. New subtask: labour-market data. Then synthesise.

The step 2 and 3 subtasks did not exist when the plan started.

## Remember
- Predictable shape → prompt chaining. Unknown shape → dynamic decomposition.
- Big review → per-file passes plus one cross-file integration pass.
- Legacy test coverage: map, then prioritise, then adapt.
- More volume is not the same as better decomposition.
